# myring

**Tagline:** Seven rings. Seven forces. One of them wants you.

**Core question:** Which ring would choose you?

**Product type:** AI-powered interactive personality game

**Primary platform:** Mobile-first web app

**Deployment:** GitHub Pages frontend + serverless API proxy for Fable 5

---

# 1. Product Summary

myring is a short, visually immersive personality game inspired by the emotional spectrum of the Lantern Corps.

Instead of answering a traditional fixed quiz, the user completes three adaptive narrative trials generated by Fable 5.

Each response changes:

* which emotional forces remain plausible
* which rings remain in contention
* the next question Fable asks
* the visual atmosphere of the experience

The user starts with seven possible rings.

After each trial, rings are eliminated.

The final surviving ring becomes the user's primary affinity.

The final result contains:

* primary ring
* primary emotional force
* affinity score
* secondary affinity
* seven-part spectrum fingerprint
* generated personality archetype
* short personalized explanation
* special result classification
* shareable result URL

The core loop is:

**Seven rings → three adaptive trials → progressive elimination → final reveal → share**

---

# 2. Product Goal

The goal is not to build an accurate psychological assessment.

The goal is to create a compelling, personalized, highly shareable AI experience that feels like:

> the ring is studying you and deciding whether you are worthy of it

The experience should feel closer to:

* a game
* an initiation
* a personality reveal
* a collectible identity result

than a normal online quiz.

---

# 3. Product Principles

## 3.1 The ring chooses the user

Do not frame the experience as:

> Which Lantern are you?

Frame it as:

> Which ring would choose you?

This gives the system agency and creates tension.

---

## 3.2 Motivation over mood

The system should identify what fundamentally drives the user's decisions.

It should not classify people based on surface-level emotional language.

Examples:

Someone expressing anger should not automatically become Red.

Someone discussing optimism should not automatically become Blue.

Someone being ambitious should not automatically become Orange.

Fable should infer the motivation underneath the behavior.

---

## 3.3 Adaptive, not fixed

There should be no fixed sequence of personality questions.

Fable chooses each next question based on:

* previous answers
* current ring scores
* ambiguity between leading rings

The user should feel that the system is reacting specifically to them.

---

## 3.4 Visually progressive

The interface should begin mostly neutral.

As the system learns more about the user, color increasingly enters the interface.

The visual progression mirrors the model's increasing certainty.

---

## 3.5 Shareability is part of the product

The result is not an end screen.

It is a social object.

People should want to:

* screenshot it
* compare results
* send their result
* challenge friends
* rerun the experience
* discuss unusual spectrum combinations

---

```text
START
  ↓

  ↓
Trial I
  ↓

  ↓
Trial II
  ↓
5 rings → 3 rings
  ↓
Trial III
  ↓
3 rings → 1 ring
  ↓
Final Reveal
  ↓
Spectrum Result
  ↓
Share / Challenge
```

# 9. Trial Structure

Each trial consists of:

1. generated title
2. short scenario
3. open-ended question
4. freeform answer box
5. Fable analysis
6. ring elimination animation

---

# 10. Trial Design

Questions should be difficult to game.

Avoid obvious questions like:

> What emotion defines you?

Avoid:

> Would you rather be hopeful or determined?

Instead use scenarios containing tradeoffs.

Possible themes:

* loss
* betrayal
* failure
* power
* sacrifice
* loyalty
* competition
* fear
* responsibility
* success
* revenge
* injustice

---

# 11. Trial I

Purpose:

Create an initial spectrum.

Fable should use a broad scenario that reveals multiple dimensions.

Example:

> You spend three years building something that matters deeply to you.
>
> The day before you launch, someone else releases a better version and receives all the attention you hoped for.
>
> What do you do next?

User answers freely.

Fable evaluates all seven forces.

Two rings are eliminated.

UI:

```text
ANALYZING RESPONSE...
```

Then:

```text
2 SIGNALS LOST
```

The corresponding rings flicker and disappear.

Five remain.

Do not show scores.

---

# 12. Trial II

Purpose:

Probe the ambiguity between the user's strongest remaining motivations.

Fable generates Trial II specifically using Trial I's answer.

Example:

If Green and Orange both score highly:

> You discover that the competing product is genuinely better than yours.
>
> You could either start again from scratch or use your resources to acquire the team that built it.
>
> What do you do?

The question should discriminate between:

* persistence
* acquisition
* hope
* revenge
* compassion
* attachment
* fear

depending on current candidates.

After analysis:

Five rings become three.

UI:

```text
ONLY 3 SIGNALS REMAIN
```

Three surviving rings expand and become visually dominant.

---

# 13. Trial III

Purpose:

Separate the final three rings.

This should be the most personalized question.

Fable should explicitly create a dilemma targeting the strongest unresolved distinction.

The user should feel:

> this question is clearly based on what I said earlier

The three remaining rings should appear behind the question.

After answer submission:

```text
FINAL ANALYSIS
```

Then:

one ring fades.

Pause.

Second ring fades.

One remains.

---

# 14. Final Reveal

The screen temporarily becomes black.

Text:

```text
A RING HAS CHOSEN YOU.
```

Pause briefly.

Then the winning color floods the interface.

Large central ring animation.

Example:

```text
GREEN

WILL

89%
```

Then:

```text
THE UNYIELDING BUILDER
```

# 19. Primary + Secondary Identity

The system should emphasize combinations.

Example:

```text
GREEN × BLUE

WILL POWERED BY HOPE
```

Another user could receive:

```text
GREEN × RED

WILL SHARPENED BY RAGE
```

This makes results more differentiated than seven categories.

There are 21 primary-secondary combinations.

# 20. Special Classifications

## Perfect Resonance

Condition:


## Dual Spectrum

Condition:

```text

```

**DUAL SPECTRUM**


## Spectrum Anomaly

Condition:

---

## Pure Signal

Condition:

```text

```

Display:

**PURE SIGNAL**

Default classification.

# 23. Visual Progression

The interface should become increasingly colorful as certainty increases.

## Beginning

Almost entirely monochrome.

Seven tiny color sources.

## Trial I

All seven colors subtly present.

## After Trial I

Only five colors remain.

Background begins leaning toward likely outcomes.

## After Trial II

Three colors dominate.

Large radial gradients appear subtly behind the interface.

## Trial III

Only final three colors remain.

## Result

Winning color dominates the entire page.

Secondary color appears in details and spectrum visualization.

The visual experience itself should communicate narrowing probability.

# 30. System Prompt

Use approximately:

```text
You are the assessment engine for myring.

myring determines which emotional-spectrum ring would choose a user.

The seven possible forces are:

GREEN = will
YELLOW = fear
RED = rage
ORANGE = avarice
BLUE = hope
INDIGO = compassion
VIOLET = love

The objective is to infer the motivational force that most reliably causes the user to act.

Do not classify based solely on emotion words.

Infer motivations from decisions, tradeoffs, priorities and behavior.

The assessment contains exactly three trials.

Each trial must use a concise hypothetical dilemma.

Questions must:
- require a tradeoff
- avoid directly naming the emotional forces
- avoid obvious personality-test wording
- use previous answers when generating later questions
- become increasingly personalized

Trial 1:
Assess all seven forces broadly.

Trial 2:
Focus on distinguishing the strongest remaining possibilities.

Trial 3:
Explicitly discriminate among the final three candidates.

Maintain normalized scores for all seven forces.

After each response, return structured JSON.

For intermediate stages return:
- updated scores
- rings to eliminate
- next trial title
- next scenario
- next question
- short internal rationale

After Trial 3 return:
- primary ring
- secondary ring
- all seven scores
- archetype
- concise explanation
- evidence from the user's answers
- a one-line identity statement

Do not expose internal reasoning or chain of thought.

Do not use random scoring.

Scores should reflect the user's actual answers.
```

# 31. API Architecture

Because the frontend will be hosted on GitHub Pages, never expose the Fable API key in frontend JavaScript.

Architecture:

```text
Browser
   ↓
GitHub Pages
   ↓
Cloudflare Worker
   ↓
Fable 5 API
```

The Cloudflare Worker:

* stores API secret
* accepts frontend requests
* sends requests to Fable
* validates output
* returns JSON

No database required for MVP.

# 49. Success Criteria

The product succeeds if:

1. A new user understands the premise within five seconds.
2. The assessment takes under two minutes.
3. Each trial feels meaningfully connected to previous answers.
4. The user feels tension as rings disappear.
5. The reveal feels visually rewarding.
6. The user wants to screenshot or share the result.
7. Two users receiving the same primary ring can still have meaningfully different results.
8. Someone watching asks to try it immediately.

---

# 50. Core Experience Summary

myring is not:

> an AI Lantern personality quiz.

It is:

> a three-stage initiation where seven possible emotional signals compete for the user, Fable progressively eliminates them based on adaptive dilemmas, and one ring ultimately chooses the user.

The emotional arc is:

**mystery → interpretation → elimination → suspense → reveal → identity → sharing**

The interface begins almost black.

The spectrum gradually appears.

By the end, the user's ring has taken over the entire screen.

That transformation is the product.
